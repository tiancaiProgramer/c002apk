# 图文混排编辑与发布

维护者：tiancaiProgramer。开发日期：2026-10-27（Asia/Shanghai）。

## 入口与界面

登录后进入首页“动态”，点击右下角“＋”，在按钮旁的菜单中选择：

- 发动态：原有文字加附图的编辑窗口。
- 写图文：可将文字段落、图片、文字段落交替排列的独立编辑页。

菜单右下角对齐加号中心，向左上方展开，两项之间使用主题细分隔线。图文页参考使用者提供的官方截图：顶部关闭、预览和发布；题图、标题、分隔线及无卡片边框的连续正文。沿用 `C001apkComposeTheme`、Material 3 圆角、按钮与主题色，并跟随应用的深色模式、字体、内容缩放和触感设置。宽窗口中限制正文编辑宽度，避免输入行无限延伸。现有话题、产品、应用详情中的动态入口继续沿用原行为，本次不更改其发布类型。

填写标题，在正文中放置光标后从底部选图，图片插入该位置，光标前后的文字分别保留。底部与动态保持相同的五项工具及原图标：表情、图片、文件选图、@、话题；表情复用最近/默认/酷币分组，@ 和话题复用原选择页面。图片可填写说明，右上角可移除；更多菜单中可移动或删除当前段。题图单独选择，可省略。顶部“预览”展示最终内容顺序，“发布”先确认可见范围，再上传与提交。

## 草稿与失败处理

- 按账号分开保存本机草稿，编辑后自动保存。所选图片复制到应用私有目录，不依赖临时文件授权。
- 草稿仅保存在本机，不自动同步服务端。清空草稿会删除该草稿的本机图片副本；不删除系统相册原图。
- 上传逐张等待成功，按图片标识关联 URL，而不是按异步回调先后顺序关联。全部成功才允许提交文章。
- 网络失败或业务失败保留草稿，不自动重试发帖，避免重复创建。请求超时后应先检查个人主页，再决定是否重发。
- 使用原有手动图形验证码流程；其他服务端验证或限制直接提示，未实现的验证不视为发布成功。
- 仅服务端返回新实体 ID 才显示发布成功并清除草稿。发布期间阻止编辑和重复提交，登录账号变化时停止提交。

## 请求格式与来源

继续使用项目已有 `POST /v6/feed/createFeed` 表单接口：`type=feed`、`is_html_article=1`。`message_title` 和 `message_cover` 分开提交；`message` 为有序 JSON 数组，文字块使用 `type=text/message`，图片块使用 `type=image/url/description`。`pic` 留空，避免把正文图片再次作为集中附图发送。可见范围使用 `publish_status`。

项目现有 `message_raw_output` 图文阅读模型用于核对内容块结构。请求字段另参考开源实现 [coolapk-desktop 的文章序列化](https://github.com/daimiaopeng/coolapk-desktop/blob/main/src/utils/publishArticle.ts) 和 [请求表单](https://github.com/daimiaopeng/coolapk-desktop/blob/main/src-tauri/src/coolapk/client.rs)，本功能为独立 Kotlin/Compose 实现，未复制其界面源码。图片上传复用本项目的凭据接口及回调格式。

这属于源码和协议实现对照，不能替代真实服务端验收。编辑布局参考使用者提供的官方图文编辑截图，未将截图或其中正文、照片打包进应用。本次没有从官方 App 新增采集文章发布请求，也没有自动发布测试文章。

## 验证范围

- 当前结果：应用 44 项 JVM 单元测试通过（其中新增图文契约测试 5 项、菜单位置测试 2 项），Debug、AndroidTest 与开启 R8 的 Release 构建成功。第二版预览版本名为 `0.1.5-article-preview.2`，versionCode 263。后续 3 项离线真机测试通过：菜单右下角与加号中心的实际屏幕坐标误差不超过 1 像素、分隔线与两项选择、连续正文预览、草稿重建恢复、深色模式、表情分组及实际光标选区到图片导入后保留前后文字。早期 Activity 启动等待未完成的尝试不计为通过；补测使用受 DUMP 权限保护的 Debug 专用 Shell 启动入口，Release 编辑页仍不导出。
- JVM 测试：交替段落顺序、特殊字符、题图与标题独立字段、图片身份关联、缺图拦截、草稿序列化与排序、可见范围。
- 离线真机测试：以虚拟账号和程序生成的图片检查两项菜单、混排编辑和预览、草稿重建恢复及深色主题，不使用真实账号令牌，不发送图文。
- 真实账号的图片上传、服务端图文创建、发布后逐段读回及验证码分支仍需验收。开发预览包不代表服务端发布已验证成功。
