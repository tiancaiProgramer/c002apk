# 平板横竖屏布局

维护与修复：**tiancaiProgramer**。

## 问题

0.1.3-rc.3 的主界面仅根据 `WindowWidthSizeClass` 判断是否显示列表/详情双列，没有结合窗口方向。已连接的 25091RP04C 平板在竖屏为 692dp 宽，超过 Compact 阈值，因此竖屏、横屏都会分栏；竖屏首页右侧仍保留空白详情面板。

## 修复

- 竖屏强制使用单列与底部导航，适用于宽屏平板和折叠设备的竖向窗口。
- 横屏继续按实际可用窗口宽度选择布局，空间足够时显示列表和详情双列及侧边导航；窄窗口保持单列。
- 主界面同时观察窗口宽度和配置方向；分栏判断每次组合时更新，不使用局部 lazy 值。
- 保留原有设置页不显示右侧详情的行为，不重写账号、数字联盟 ID、设备参数或浏览数据。

## 0.1.4 横屏导航位置

根据当前窗口约束重新计算位置，适应不同屏幕、旋转和分屏尺寸。扣除侧边导航使用的系统安全区域及上下内边距后，首个按钮的额外顶部留白为可用高度的 8.1%，按钮中心间距为可用高度的 13.1%；额外左侧留白为可用宽度的 1.085%。这些比例以已确认的平板效果为基准。

按钮本身保留 Material 3 的尺寸；小窗口的中心间距至少为 60dp，避免点击区域重叠。高度紧张时收缩顶部留白，优先显示三个按钮。竖屏底部导航不应用此比例调整。

横向比例使用完整窗口宽度，避免首页双栏时把半屏主列表误当作整个窗口。比例布局候选包已在 25091RP04C 平板覆盖安装，导航位置与此前确认效果一致。正式版本名保持 0.1.4，内部 versionCode 261，替换早期固定间距构建。

## 验证范围

方向与宽度测试覆盖竖屏 Medium/Expanded、横屏 Compact/Medium/Expanded，以及配置切换；比例布局另覆盖基准平板像素位置、不同窗口尺寸按比例缩放和较小窗口中按钮不重叠，完整单元测试为 45 项。

真实设备修复前截图、修复后的横竖屏截图和旋转设置仅保存在本地验证目录，不随公开附件上传。最终安装、横屏双列、返回竖屏单列及原旋转设置恢复的结果，以 Release 的 VALIDATION.json 为准。当前更改不重跑登录/评论发送及图片/二手交易专项。
