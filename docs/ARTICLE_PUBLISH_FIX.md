# 图文发布排版与原稿保护

维护与修复：**tiancaiProgramer**。2026-10-28，本地修复和设备验证；未经用户再次明确要求，不推送或发布 GitHub。

## 已确认原因

同一账号、可见范围、请求配置和内容块结构下，私密短文在服务器返回 `is_html_article=0`、`feedType=feed`、`message_raw_output=[]`，文字被合并，图片集中到末尾，说明不再存在。延长正文后，同样的三段文字/两张图片交替结构返回 `is_html_article=1`、`feedType=feedArticle`，五个块和两条图片说明均被保留。

这是实际设备的长短正文对照结果。没有测定服务器的精确字数阈值，不硬编码猜测的最小字数，也不自动添加填充正文。客户端不能从已经丢弃信息的普通动态恢复原排版。

临时改变客户端协议版本未解决短文转换问题，已全部撤回；最终修复使用原有账号及设备协议设置。临时诊断拦截器也已移除。私密范围继续使用 `status=1`、`publish_status=1`；不使用已被服务端拒绝的旧 `status=-1`。

## 修复行为

- 发布确认解释短图文可能被转为普通动态，造成混排和说明丢失。
- 创建成功后读回详情，逐块检查文字/图片的先后顺序、文字内容、图片 URL 路径身份及图片说明。对刚发布内容进行有限的只读重试，不重复创建。仅核验通过后才清除本机草稿与导入图片副本。
- 服务端已创建普通动态，或详情暂时无法确认完整时，显示明确的结果提示并保留原稿。已得到创建 ID 的当前会话禁止再次提交，提醒先检查个人主页，避免重复创建。
- 详情解析统一处理空值、字符串 `null` 和空数组，按服务端数组顺序保留内容。Gson 可绕过 Kotlin 默认构造初始化，所以不再依赖内容块默认 UUID，改为解析时分配唯一且稳定的列表标识。
- 图文标题优先显示 `message_title`，兼容旧的 `title` 字段。
